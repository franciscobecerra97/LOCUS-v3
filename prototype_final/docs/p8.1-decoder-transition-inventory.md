# P8.1 Decoder and Durable-Transition Assurance Inventory

Status: Complete.

This is the human-readable companion to
`p8.1-decoder-transition-inventory.json`. The JSON inventory is checked by
`tests/test_p8_1_assurance_inventory.py`; it maps the active external decoders,
routes, durable transitions, and cross-cutting controls in `prototype_final/`
to named negative, retry, concurrency, and authenticated-transport checks.

This document and its JSON companion are implementation-governance artifacts.
They are not retained P8/P9 evidence, assign no evidence identifier, and do not
authorize a manuscript claim.

## Scope and method

The audit covers:

- the canonical mTLS RPC envelope;
- Admission, Operator/discovery, Resolver, storage-gateway, and five Party
  service routes;
- the loopback Manager API, internal controller API, and managed Client API v2;
- descriptor, pointer, bundle, recovery-package, backup, suite, policy, and
  deployment-configuration codecs;
- admission replay, immutable object publication, descriptor CAS, Party suite
  and current-epoch state, enrollment/recovery journals, successor publication,
  bootstrap-owned files, controller lifecycle state, and managed Client
  volatile state; and
- path and symlink containment, simultaneous and stale lifecycle operations,
  resolved/live graph mutation checks, and prohibited-output scanning.

The checker independently extracts every active route literal from
`integrated_services.py`, `integrated_manager.py`,
`integrated_controller.py`, and `managed_client_ui.py`. It requires exact
equality with the route set in the JSON inventory and verifies that every
cited source and test symbol exists. Adding an external route without adding
its assurance row therefore fails `integrated-check`.

## Coverage result

Every inventoried external surface has both named negative coverage and a
named authenticated-transport/configuration exercise. Every inventoried
durable transition has an exact retry, conflict, crash/restart, concurrency,
or state-preservation check appropriate to that transition.

The principal live control remains `tasks.py integrated-smoke`. It traverses
the D025 Manager-created Client-to-service graph, all four suite/topology arms,
all valid threshold subsets, lifecycle restart/kill/start behavior, successor
retirement, preserved-state restart, destructive reset, and output/state
audits. P8.1 adds two explicit full-system schedules:

- two simultaneous Manager create requests with one operation identifier must
  return the same exact Client and leave exactly one inventory entry; and
- an action against a stale/nonexistent container identifier must fail closed
  through the public Manager transport without changing the live Client.

The mTLS transport also has a live loopback test proving TLS 1.3 client
certificate enforcement, authenticated peer-role extraction, and rejection of
a duplicate-member request before handler dispatch.

## Defects closed during the audit

The audit identified and fixed three path-boundary defects:

1. filesystem backup reads/deletes now reject a symlinked backup namespace;
2. filesystem descriptor paths now reject any symlinked ancestor below the
   configured root, including nested locator paths; and
3. integrated bootstrap rejects a symlinked role root before examining or
   writing role state.

Positive-control tests attempt the corresponding escapes and require explicit
rejection. Where the host OS denies creation of test symlinks, the test is
reported as skipped instead of weakening or emulating the boundary.

## Interpretation limits

P8.1 establishes implementation assurance for the exact D025 same-host system.
Unit/property tests do not prove cryptographic results. Same-host containers do
not establish independent administration or multi-host separation. The live
smoke is a disposable development gate and does not become retained P8.2/P8.3
evidence. P8.2 and P8.3 collection remains blocked until their exact schemas,
trace/path rules, output rules, and cleanup contracts are presented to and
approved by the owner.
